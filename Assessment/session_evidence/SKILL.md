# Agent Evidence Assessment Meta-Skill

## Purpose

Assess what an individual learner has *demonstrated* from three evidence channels:

1. **Agent sessions** — contemporaneous interaction, decisions, corrections, tool use, and feedback.
2. **Outputs/artifacts** — task specifications, code/diffs, policies, traces, tests, reports, and other deliverables.
3. **Reflections** — retrospective explanations, tradeoffs, judgments, and prospective insights.

This is a **meta-skill**. Load an assessment profile/rubric supplied with the task, then use the common evidence, attribution, and triangulation rules in this package. The profile defines target constructs, task knowledge, reporting format, and any performance boundary.

---

## Non-negotiable rules

1. **Session reasoning is not automatically learner reasoning.** Anything generated by the Agent, tool, harness, evaluator, IDE, or system is not evidence of the learner's cognition unless the learner visibly evaluates, modifies, rejects, selects, or applies it.
2. **A `user` role is not automatically a human statement.** Inspect content type. Tool results, IDE context, hook messages, imported context, and coordinator prompts may be encoded as `user`.
3. **Do not infer ability from absence without opportunity.** `No opportunity` and `not preserved in the record` are not low ability.
4. **Recognize proactive regulation.** A learner may prevent a failure before it occurs. Rote execution of a supplied rule is procedural evidence unless the learner visibly adapts it to current conditions.
5. **Do not count derivative evidence as independent corroboration.** If a reflection was Agent-written, or a report merely restates another report, preserve the lineage and do not multiply confidence.
6. **Do not treat automated evaluation scores as ground truth.** They are evidence sources with their own scope.
7. **Keep assignment scoring and ability inference separate.** A rubric may require a submitted item; failure to submit it may lower coursework score, while person-level ability remains `not established` rather than `low`.
8. **Do not combine profile constructs into one global ability score unless the supplied rubric explicitly requires it.**
9. **Do not claim causal development from cross-sectional evidence.** Only claim a developmental sequence when a temporal chain is actually observed. Otherwise say evidence is *consistent with* the profile's developmental model.
10. **Do not expose hidden chain-of-thought.** Base claims only on observable session content, actions, tool outputs, artifacts, and reflections.

---

## Required inputs

At minimum:

- one learner submission bundle (directory or ZIP; nested ZIPs allowed), and
- an assessment profile or rubric describing the target constructs.

Recommended when available:

- authoritative assignment brief,
- starter prompts/templates/scaffolds supplied to learners,
- course/tutorial knowledge source,
- teacher calibration examples.

If any recommended input is missing, proceed but state the resulting inference limit. In particular, without the assignment brief, be cautious about calling a behavior `independent` rather than `scaffolded`.

An assessment profile is required because it determines what the learner is being assessed for. Read [the profile contract](references/profile_contract.md) before assessment. If no usable profile is supplied, do not start construct assessment or infer a substitute profile. Ask for the minimum missing profile fields in one concise request.

## Workflow

### Phase 0 — Load the assessment profile and distinguish two axes

Apply two independent axes:

- **Task or teaching unit:** use the profile's taught knowledge points, task anchors, and construct definitions. A profile may designate constructs that remain stable across its units.
- **Evidence modality:** selectively apply the profile's constructs according to observable content, attribution, and opportunity. Do not create different definitions of a construct for sessions, outputs, or reflections.

Agent sessions are the primary evidence source for applicable profile constructs. Outputs and reflections, when available, supplement this assessment after their own qualitative analysis. Read [the evidence model](references/evidence_model.md) for the selection and triangulation procedure.

Read the supplied rubric/profile before inspecting the learner. Extract:

- constructs and operational definitions;
- scoring items and anchors, if any;
- unit/task-specific knowledge points;
- evidence thresholds;
- required vs optional deliverables;
- assignment conditions (baseline, constrained run, experimental perturbation, etc.).

Never silently replace the supplied rubric with generic knowledge.

### Phase 1 — Build an evidence manifest

Inventory the entire submission, including nested archives, with available filesystem and archive inspection tools.

Classify each source as one or more of:

- `session`
- `artifact/output`
- `reflection`
- `evaluation/report`
- `assignment/scaffold`
- `course/rubric`
- `other`

Record at least:

- source path / archive chain;
- file type;
- likely task/unit/phase;
- whether content appears original or derivative;
- parsing/coverage limitations.

Do not assume folder names determine the task phase.

### Phase 2 — Normalize session events

For each session, derive observable events without rewriting the original evidence.

Recommended event classes:

- `human_text`
- `agent_text`
- `human_decision`
- `human_correction`
- `human_request`
- `tool_call`
- `tool_result`
- `artifact_write`
- `evaluation_result`
- `system_or_ide_context`
- `unknown`

Preserve timestamps and original source pointers when possible.

Special handling:

- A tool result wrapped in a `user` message remains `tool_result`.
- IDE selections, imported files, hooks, and environment injections remain context, not learner claims.
- Agent reasoning or analysis can explain what the Agent did but never counts as learner cognition.

### Phase 3 — Establish evidence lineage

Before construct coding, check whether sources are dependent.

Examples:

- Agent writes `reflection.md`; learner submits the same file -> one evidence lineage, not two.
- `comparison_report.md` summarizes `baseline_eval.md` and `final_eval.md` -> derivative report.
- A final evaluation quotes test logs -> evaluation and logs are linked, not independent confirmations.

For each important source, mark:

- `primary/contemporaneous`
- `primary/artifact`
- `retrospective`
- `derivative`
- `automated-evaluation`
- `unknown-provenance`

### Phase 4 — Segment meaningful episodes

Do **not** score prompts, retries, or test counts directly.

Segment sessions around meaningful `decision/adaptation episodes`. A typical reactive episode is:

`goal/current belief -> feedback or discrepancy -> recognition -> diagnosis/evaluation -> change -> verification`

A proactive episode may be:

`anticipated risk -> task-specific rationale -> preventive control -> check/monitoring condition`

An episode may be incomplete. Preserve missing steps instead of filling them in.

Use [episode and attribution rules](references/episode_and_attribution_rules.md), plus the construct rules selected by the profile.

### Phase 5 — Attribute the cognitive work

Assign one primary attribution label to each construct-relevant event/episode:

- `learner_initiated`
- `agent_proposed_learner_evaluated`
- `agent_proposed_learner_accepted`
- `teacher_or_assignment_scaffolded`
- `agent_led`
- `harness_or_tool_automatic`
- `mixed_or_unclear`

Attribution is not a moral judgment. It limits what can be claimed about individual ability.

General admissibility:

- Learner initiates, diagnoses, or gives task-specific rationale -> strong individual evidence.
- Agent proposes; learner critiques/modifies/selects with reasons -> moderate-to-strong evidence depending on depth.
- Agent proposes; learner says only “yes/continue/save it” -> weak evidence.
- Agent autonomously diagnoses/fixes/tests -> system-performance evidence, not learner regulation.
- Teacher scaffold is followed correctly -> may support profile-defined knowledge application, but independence should be qualified.

Before crediting learner planning, compare candidate prompts with the supplied assignment and starter templates. Record the learner's observable adaptation or evaluation beyond the scaffold. Copying a planning prompt alone does not establish a profile-defined planning or regulation construct.

### Phase 6 — Code opportunity

For every selected construct or profile subcomponent, determine whether the record provided an opportunity:

- `direct_opportunity`
- `proactive_opportunity`
- `no_clear_opportunity`
- `opportunity_unknown_due_to_coverage`

Examples:

- No failure occurs because the learner creates a task-specific preventive control with a rationale -> proactive opportunity for a regulation construct.
- Agent succeeds immediately and no evidence-sensitive learner decision is visible -> no clear opportunity for reactive regulation.
- Session starts midway through work -> opportunity unknown.

Never convert `no clear opportunity` into evidence of low ability.

### Phase 7 — Map evidence to constructs

First qualitatively analyze session content and apply the profile's construct rules to establish provisional claims. Treat every profile construct as eligible, but establish each only where admissible evidence exists.

For each supplementary output or reflection, qualitatively analyze its content before selecting constructs. Record which dimensions it can inform, source pointers, and why other dimensions lack an observation opportunity or adequate coverage. Do not infer suitability from the filename or force every modality to measure all constructs. Use the selection procedure in [the evidence model](references/evidence_model.md).

For each construct, build **claims**, not just scores:

- claim text;
- supporting evidence pointers;
- attribution;
- opportunity status;
- contradictory/limiting evidence;
- evidence strength;
- confidence.

Use the profile's operational definitions and exclusions for each construct. Preserve existing course-item scores where the profile requires them; use them as evidence for construct interpretation rather than silently creating an overlapping score.

### Phase 8 — Triangulate across source types

Start from the provisional session-based assessment, then compare the selected dimensions of supplementary modalities claim by claim using [the evidence model](references/evidence_model.md). Record corroboration, complementary evidence, contradiction, derivative repetition, or no relevant evidence, and explain any resulting change in the conclusion or confidence.

Supplementary sources can strengthen, qualify, or challenge session-based conclusions. Session priority does not override contradictory direct evidence. If sessions are missing or incomplete, continue with bounded supplementary-source claims and make the session coverage gap explicit. Do not average modality scores or count derivative sources as independent confirmation.

### Phase 9 — Apply rubric scoring, if requested

If the assessment profile contains assignment scoring anchors:

1. Score each rubric item using the rubric's own evidence threshold.
2. Cite direct evidence for every score.
3. Do not let one construct compensate for a missing requirement in another unless the rubric allows it.
4. Keep `coursework score` distinct from `ability evidence strength`.

### Phase 10 — Generate the personal analysis

Use [the report contract](references/report_contract.md).

Required characteristics:

- evidence-linked;
- source and attribution aware;
- opportunity-conditioned;
- explicit about uncertainty;
- developmental rather than merely judgmental;
- no global trait claims that exceed the observed tasks.

Prefer phrases such as:

- `demonstrated in this task`
- `supported by multiple independent sources`
- `suggestive but not independently established`
- `Agent-led; does not establish learner regulation`
- `not observed because no clear opportunity was preserved`
- `conflicting evidence`

Avoid phrases such as:

- `the learner is highly metacognitive` from one episode;
- `the learner cannot ...` based on missing evidence;
- `three sources confirm ...` when the three are copies/derivatives;
- `high performance proves high ability`.

### Phase 11 — Optional performance handoff

If the profile separates task-performance evidence from learner constructs, produce a compact handoff:

- task/feature;
- verified outcome evidence;
- unverified claims;
- relevant tests/runtime checks;
- task conditions;
- known blockers.

This handoff can be consumed by a separate AI-augmented performance skill.

## Evidence strength labels

Use these for person-level claims; they are not rubric points.

- **Strong** — clear learner attribution, direct task evidence, appropriate opportunity, and either consequential behavior or independent corroboration.
- **Moderate** — relevant learner evidence exists but attribution, coverage, boundary conditions, or corroboration are incomplete.
- **Limited** — mostly retrospective, scaffolded, acceptance-only, or single-fragment evidence.
- **Not established** — an applicable construct lacks sufficient admissible evidence.
- **Not observable** — no clear observation opportunity; record unknown coverage separately when it prevents deciding applicability.
- **Conflicting** — meaningful evidence points in different directions and cannot be resolved from the record.

Confidence (`high / medium / low`) is separate from strength. For example, there can be high-confidence evidence that a construct is *not established by the available record*.

---

## Stop conditions / ask for clarification only when necessary

Do not block assessment merely because some evidence is missing. Continue and qualify.

Ask for clarification only if one of these prevents meaningful interpretation:

- learner identity cannot be mapped to a submission at all;
- the supplied rubric/profile is ambiguous about which unit/task to score;
- multiple authoritative assignment briefs conflict materially;
- a requested numeric score cannot be computed because the scoring scale itself is absent.
